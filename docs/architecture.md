# Architecture

The file index is a cache of observed names and identities. The event cursor is a delivery checkpoint backed by a durable work queue. The recovery journal is a separate record of mutations. Losing the cache can require reindexing; losing recovery records can prevent reverting names.

The production app has two long-running processes: a Rust worker/CLI and an AppKit menu application. Within the worker, one thread owns filename mutations and a separate source thread owns coverage discovery and native stream lifecycle. A shared metadata watchdog interrupts stalled read-only operations on their originating threads. The menu issues CLI commands and presents their results. Both executables are packaged in `Jaso NFC.app`.

`CFBundleExecutable` names the Rust executable used by the worker LaunchAgent. A normal application launch with no CLI command uses `exec` to transfer into the menu executable, retaining no intermediary process. The main and GUI executable names, bundle identifier, and application type are checked against one shared contract before dispatch or installation. Explicit CLI commands bypass GUI dispatch. This aligns the selected app with the worker executable, but bundle tests do not establish a live macOS privacy grant. Closing windows keeps monitoring active; app Quit explicitly stops the worker before exiting.

The earlier implementation in `src/jaso_nfc/` remains a compatibility reference. Its configuration signatures, SQLite state, pending records, retries, and retained journal formats are migration inputs rather than a Python runtime dependency.

## Delivery and acknowledgement

A native callback copies paths, flags and IDs before returning. It submits a batch in one transaction: advancing a cursor without its corresponding work is forbidden. Jobs coalesce by directory. An event received while a job is executing changes its generation, so the running job cannot delete newly arrived work.

The worker scans one directory outside the database lock. It applies the resulting entry changes, acknowledges that generation and queues any recursive continuations together. A crash after a rename but before the index transaction leaves work to replay. Actual stored names and identities are re-read, making reconciliation repeatable. `baseline_walks` counts starts of configured roots; `subtree_scans` counts individual directory visits carrying recursive intent.

The complete index and traversal frontier remain in SQLite. Ordinary event work is coalesced and capped; durable traversal continuations are retained on disk rather than collapsed repeatedly back to a root. In-memory scan results cover one directory, so a single exceptionally wide directory can still require additional memory. SQLite uses a bounded page cache. When there is no pending work or retry deadline, the worker blocks on its wakeup FIFO. Native callbacks, signals and explicit reconciliation requests notify that descriptor; no helper polling thread or idle polling timer is used.

Initial streams start before enumeration. Their captured initial IDs are persisted even when no event arrives during the first scan. Configuration changes and volume UUID changes invalidate incompatible index state. Transient device numbers identify current native streams; the volume UUID identifies persistent history. Each configured root gets a distinct checkpoint keyed by its volume UUID and logical root. The device-relative API accepts one watched path per stream despite its array parameter; sharing a cursor across independently delivered root streams could skip lagging work.

In automatic coverage mode, fixed account and mount catalogs are observed separately from the data roots. Discovery examines directory metadata rather than recursively scanning documents. New roots get durable pending baselines; removed roots relinquish their active coverage without clearing unrelated indexes. Independently indexed cloud roots under an excluded home Library survive a broader home reconciliation. An unavailable root or catalog is recorded explicitly and retried without turning the worker into a periodic whole-system scan.

## Event policy

Ordinary file events request a shallow containing-directory enumeration. Pure content or metadata notifications for an already indexed regular file with an NFC name only advance the event cursor; they do not request another directory scan. Unknown paths, decomposed names, directory events, lifecycle changes and unknown flags retain conservative reconciliation. Entry size and timestamps therefore describe the last enumeration, not a continuously refreshed content inventory.

New or moved-in directories and `MustScanSubDirs` request a recursive subtree reconciliation. Dropped events, wrapped IDs or queue overflow require broader reconciliation of the affected stream roots. `HistoryDone` is a control event, never a pathname. Root or mount changes trigger root/volume revalidation. When the UUID, mount and watched roots are unchanged, revalidation preserves the acknowledged cursor while staging reconstruction; historical mount notifications cannot repeatedly reset replay to the beginning.

FSEvents is advisory. An explicit `reconcile` command is available when another tool or filesystem invalidates the observed state without useful events. Normal idle operation has no whole-root periodic scan.

Due rename discovery uses saved deadlines and parent paths without re-enumerating the failed folder on every worker step. Successful parent enumeration removes retry records whose item disappeared or already has its normalized stored name. Ready baseline work, ordinary events, and due failed jobs take turns; jobs whose retry deadline is still in the future remain delayed. An event or manual request below a pending baseline keeps ordinary service for its requested path instead of waiting for the ancestor's entire initial traversal. Baseline bookkeeping remains pending until that traversal finishes. Rediscovering a failed child preserves its retry deadline. This prevents a growing initial traversal from starving retries and repeated failures from continually displacing other work.

Retry records track changes through an encapsulated map. An unchanged save reuses the last successful persisted revision; a failed write remains eligible for another save. A derived, sorted deadline index is rebuilt after record or policy changes, so ordinary scheduling checks only due entries. Wall-clock regression still clamps excessive deadlines. An existing eligible directory job or recursive ancestor owns its retry ticket, preventing rediscovery from repeatedly changing the queued generation. The durable retry JSON format and rename recovery synchronization order stay compatible.

Live ordinary requests receive a bounded burst of at most 256 observations or one second before yielding to failed, baseline, and saved backlog work. The next selection checks elapsed monotonic time, so a slow ordinary operation also ends its burst. This amortizes a slow provider retry across several cheap local changes while preserving background turns; absent classes are skipped without waiting. The burst uses only in-memory counters and creates no timer or additional thread.

Explicit ordinary requests use FIFO order within their ready group. Coalescing preserves a queued request's place; promoting a baseline-only row or retaining a newer generation after an observation places that ordinary work at the tail. Thus a frequently changing short path cannot repeatedly jump ahead of deeper requests. Implicit traversal work retains its separate priority, and persisted retry deadlines still apply.

On restart, saved ordinary requests resume as backlog rather than preceding all live changes. The worker records the existing queue's row-ID boundary in memory. A high-water mark in the existing metadata table keeps new explicit requests above prior startup boundaries and intake positions, including requests written by a separate CLI process after older jobs have drained. Newer explicit requests receive live service, while baseline, due failures, and saved/implicit ordinary work each receive background turns. A new external request for an old pending path promotes it to live intake. Incidental traversal or retry rediscovery preserves its background position. This separation adds no thread or on-disk schema.

Each job records the depth of ordinary work separately from its pending baseline. A shallow event at the same path does not promote the whole baseline subtree into ordinary work, and completing it does not mark the baseline finished. Both intents survive a restart; later baseline expansion preserves pending ordinary descendants.

Index writes reserve the SQLite writer before reading the state they will update. A manual reconcile request can then wait for an active background transaction instead of failing while promoting an outdated read snapshot to a write. Directory enumeration and filesystem-aware policy checks stay outside the worker's index transactions. Event intake and index updates use lexical boundaries; the normalizer validates actual filesystem boundaries before mutation.

On macOS, directory opens and enumeration temporarily allow dataless directory materialization on the calling thread and restore its prior policy afterward. Regular file opens retain the prior policy. This lets the provider supply a directory's child metadata when a background process would otherwise receive `EDEADLK`; provider unavailability can still fail and remains queued. See [Apple TN3150](https://developer.apple.com/documentation/technotes/tn3150-getting-ready-for-data-less-files) and [Apple's File Provider enumeration explanation](https://developer.apple.com/videos/play/wwdc2021/10182/).

Directory metadata access has a progress deadline so a stalled cloud provider does not indefinitely hold up the worker. Normal progress extends the deadline, allowing large folders to finish. A timeout discards the incomplete listing, preserves the previous index, and uses the existing retry backoff. One watchdog with a 128 KiB stack tracks independent deadlines for discovery and normalization threads and sleeps when no directory operation is active. It does not create threads or processes per folder. Each signal targets only the thread performing the scoped directory operation, and scope cleanup cancels delivery and drains pending signals before restoring the prior mask. Rename and file-content operations are outside this scope.

Stored-name resolution is also bounded, including metadata-only entry opens, `F_GETPATH`, and identity checks before directory enumeration starts. These entry reads preserve the caller's materialization policy; only directory operations enable directory metadata materialization. A timed-out read cannot return an apparent successful spelling, and any descriptor acquired before expiration is closed normally.

Startup catalogs and FSEvents root identity checks use the same deadline mechanism. Access checks open and close a directory without enumerating its children. Catalog enumeration uses raw directory calls so an automatic `EINTR` retry inside a higher-level helper cannot hide the deadline. Incomplete catalogs are reported as unavailable while discovery continues for other locations; device, inode, and physical-path checks still reject a replaced or remounted root. Discovery retries are scheduled from completion, so a slow discovery pass cannot make the next retry immediately overdue and crowd out indexing.

Discovery runs independently of mutation scheduling. A blocked catalog probe therefore cannot prevent a healthy root's queued work from receiving a turn. Persisted coverage describes the last completed discovery and can reflect an earlier run until a new worker completes source discovery. Its file timestamp changes only when the saved content changes; neither that timestamp nor an active-root listing proves timely processing of new file events. Existing healthy streams remain active when a neighboring root cannot start. A newly prepared volume stays inactive until its stream has started, preserving stream-before-scan ordering even when old jobs are already on disk. Previously known but temporarily unavailable volumes retain their identity, cursor, jobs, and observations as inactive state; explicit scope removal still removes disposable index state for that scope.

Worker observations use a two-phase directory snapshot. Enumeration collects small batches into a private temporary SQLite database, then filename operations consume small batches from that snapshot. Each phase handles at most 128 children and checks a 75 ms budget between operations. These are scheduling budgets, not a hard latency guarantee: a single filesystem operation can take longer, subject to its metadata deadline. At most eight snapshots retain directory descriptors; each uses a 64 KiB SQLite page cache. Removed jobs release their retained snapshot slots.

Partial observations can add positively observed entries but cannot infer that unseen entries disappeared. A complete observation permits pruning only after all of its batches are accounted for. Failed listings preserve earlier evidence, and a restart re-observes an unfinished snapshot. Before resuming, descriptor identity must still match the directory at the selected path. Name mutations continue to use the existing durable pending record, identity checks, and journal synchronization.

Dot-prefixed directories are excluded below scan roots, covering home application data, nested caches, and cloud-provider temporary folders. An explicitly selected hidden root remains eligible, while hidden subdirectories still follow the boundary. The `.tmp` directory directly under a Google Drive provider root and its descendants remain excluded even when explicitly selected. Ordinary dotfiles remain eligible unless excluded by saved configuration. Policy binding retires excluded persisted jobs and index observations while retaining allowed scan cursors. Existing package, `.git`, and explicit exclusion guards remain authoritative.

Paths returned from per-device streams are relative to the physical volume. On APFS, logical paths can cross firmlinks. The adapter obtains the physical path with `F_GETPATH_NOFIRMLINK` and the mount with `fstatfs`, validates identity, and maps events back to configured logical roots. NFC and case-folded strings are not unique file identities.

## Mutation and recovery

Regular-file name targets combine NFC normalization with conservative Korean encoding repair; directory, symbolic-link, and other special entry names use NFC normalization. Keeping directory spelling changes within canonical normalization preserves the meaning of saved exclusion and history paths. The file repair path considers original UTF-8 or CP949 bytes misread as Latin-1 or Windows-1252, requires lossless round trips and sufficient evidence, and leaves ambiguous candidates unchanged. CP949 candidates additionally require a term from a curated Korean filename vocabulary and corruption artifacts; another valid interpretation prevents repair. Preview and mutation use the same target calculation. Encoding repair uses the existing identity, collision, pending-operation, and history protocol.

The `filename_policy_revision` migration stages retained, verified roots once for the new filename rules. It preserves existing event cursors and indexed entries while queuing that reconciliation.

Name changes run serially. Directory-sized worker steps queue descendants using their parent's actual final name. A pending record containing paths and object identity is made durable before a mutation. Destination existence is never permission to replace a different object. Temporary-hop recovery and identity checks handle normalization-insensitive lookup. Successful records are appended and synced before clearing pending state. File and directory durability use POSIX `fsync`, preserving the established synchronization order. Ordinary failures use bounded diagnostics and persistent backoff; recoverable operations remain in retained history.

Observed entries store each directory prefix once and use a parent identity plus basename for their key. An existing index migrates transactionally from repeated full paths, preserves queue and cursor state, and reclaims the old pages once. Identical observations leave entry storage unchanged.

Each completed rename produces one durable change record. Routine I/O phases and unchanged checks update live progress without adding activity rows. Missing metadata paths represent completed absence. Repeated errors and deferrals update an existing row for the same path and phase; a completed rename or restore starts a new outcome. History stores each completed payload once; exceptional later events retain a small projection for restoration checks. Maintenance runs under the worker lock at startup and after completed changes. Recent completed history keeps an 8 MiB active journal and up to two archives with a combined 16 MiB uncompressed budget. Expired segments are validated before deletion; unresolved recovery and active requests retain their necessary evidence. A retained fragment whose intervening history has expired cannot be used for automatic restoration. Completed restore request/result pairs retain the latest 128 pairs.

Successful installation/settings transactions mark their backups complete. Retention keeps one completed installer backup and two completed settings backups, plus incomplete recovery transactions. Installation keeps the current and latest rollback releases and any additional release referenced by recovery. Storage details separate the file index, history cache, logs, backups, app versions and other data.

If activation fails after the replacement worker has started, installation stops that worker and restores the legacy entry schema transactionally before restarting the previous app. Observations and queued work remain intact. The previous app rebuilds its history search cache from retained journals.

On macOS, the worker resolves decomposed directory-entry names with descriptor-based `F_GETPATH`: an exFAT listing may present NFD even when that object's actual descriptor path is NFC. AppleDouble companions move with their owning item and are never normalized independently. Exclusive native rename is preferred. Where unsupported, a guarded ordinary rename preserves compatibility; the final destination check and rename are not atomic against another application's concurrent destination creation. A destination created in that interval can be overwritten by the ordinary rename; a destination already detected by the check is rejected. See [implementation choices](comparison.md).

Recovery reads retained archives as a stream and keeps only the latest matching operation. Marker intent is persisted before attachment; the marker token identifies its owner even if exFAT changes the reported inode during attachment or either hop. Completion is journaled before marker cleanup, and a changed cleanup identity is recorded before clearing the intent. If that final identity cannot be established after a crash, recovery retains the known success without adopting a possibly replaced destination.

Directory enumeration failures retain previous index evidence and schedule retry. Exclusions apply to events as well as walks. Symlink and package boundaries cannot be bypassed by sending a descendant event. Recovery/state writes are outside coverage and this process's live native events are ignored to avoid feedback.


## Menu and installation

The regular AppKit application keeps a Dock presence and refreshes its compact menu summary when opened. The workspace presents Status, Activity, Folders, History, and Settings in one window. Settings owns preferences and an Advanced settings disclosure for permissions, storage, maintenance, and diagnostics; its user-guide action remains directly available below that disclosure. Mutating CLI actions use one serial command queue. Quit waits behind pending commands, requests worker stop, and terminates only on confirmed success. Installer handoff uses a separately validated GUI-only termination path so it does not invoke interactive Quit or compete with installer lifecycle control. Pause keeps event ingestion active while stopping mutation. Manual folder selection queues a subtree within the active policy. Worker start/stop and login startup are separate controls.

The activity responder waits for socket readiness and a private shutdown signal, eliminating timed acceptance checks while idle. UI activity requests share one in-flight query and a short-lived result across workspace windows. Presentation compares semantic state, including updates to existing activity rows, while generated snapshot clocks alone do not rebuild the list. Unchanged views and date formatters are reused; changed rows, session resets, filters, localization, and time-zone changes invalidate the corresponding presentation. Visible active work retains its polling cadence, with an explicit refresh path for a fresh query.

The Status view projects read-only retry metadata into per-item causes and actions. The CLI samples at most eight persisted rename failures and eight failed directory jobs, ordered by retry eligibility, while retaining their full counts. Deferred queue capacity is distinct from a failed attempt. Validated saved stat signatures can establish that an item or parent was locked at the last rename attempt; a bare operation-not-permitted error cannot establish missing Full Disk Access. Status inspection does not stat every failed path or change retry policy. Finder actions reveal the selected path without mutating it.

Activity records carry the cause and errno captured at the failing operation, along with the first and latest failure times and an occurrence count. Matching unresolved failures update one bounded event. A verified success resolves only the matching path and operation phase; completing metadata access does not establish successful folder enumeration. Incomplete observations and paths omitted from the limited current retry sample cannot resolve prior failures. Resolved entries retain their original cause and completion time. The workspace presents historical activity separately from the current retry snapshot, so a newer failure cannot replace the explanation for a past event.

Automatic coverage stores external-drive choices by volume UUID. Automatic mode admits drives except explicitly excluded identities; selected mode admits included identities. Explicit folder coverage keeps its existing roots. Drive preferences are excluded from the index policy signature, preserving the historical signature and unrelated observations when a drive choice changes. Runtime readiness uses a separate full-configuration signature so setup can acknowledge the new preferences before resuming work.

Disconnected included volumes retain their index and cursor for reconnection. Removing a drive releases its executable coverage and keeps an exclusion choice for future discovery; recovery transactions remain independent. Configured removal also retires roots belonging to that drive; an empty configured list is valid idle scope. A stored configuration contract identifies root-only reductions so unrelated cursors and observations survive. Status retains diagnostic totals and adds a `current` projection for active directory work and relevant rename retries. The native status window uses that projection and leaves disconnected drive rows to the management screen.

The menu mark repeats `ㅈㅏㅅㅗ` → `자소` over a 12-second Core Animation cycle: a separated hold, smooth composition, a composed hold, then a smooth return to the separated positions. It has no application frame timer. The animation toggle and Reduce Motion select the static composed mark. Rendering still consumes resources; this design is not a measured zero-CPU claim.

The installer stages an ad hoc signed native release in the private support directory, preserves existing state and earlier releases, and registers one worker LaunchAgent. Its `run` mode starts the native menu after worker initialization, in a detached process session, with a wait thread to reap the child. Manual `watch` does not start a GUI. The earlier menu registration is retired during migration. The installer snapshots prior files, both legacy job states and the menu process before activation, restoring them on failure where possible. `/Applications/Jaso NFC.app` contains the complete running app bundle for both processes; the immutable private release remains available for recovery. An owned legacy app in `~/Applications` is removed after activation succeeds. Full Disk Access and background-execution permission remain manual user decisions. See [installation](installation.md).

## Sources and limits

- [Unicode UAX #15](https://www.unicode.org/reports/tr15/): canonical equivalence and NFC versus NFD.
- [Apple FSEvents guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html): start monitoring before scanning, persistent per-device history, and advisory events.
- [Apple callback contract](https://developer.apple.com/documentation/coreservices/fseventstreamcallback?language=objc): buffer lifetime and native types.
- [Apple dispatch scheduling](https://developer.apple.com/documentation/coreservices/1444164-fseventstreamsetdispatchqueue?language=objc): stream scheduling and invalidation.
- [Apple public fcntl header](https://github.com/apple/darwin-xnu/blob/main/bsd/sys/fcntl.h): physical path discovery without firmlink substitution.

No watcher can repair a filesystem that refuses to preserve the requested spelling. Such cases remain observable failures with delayed retries. Recovery can identify an object still at a recorded location; it cannot locate arbitrary later moves throughout the filesystem.
